# Messager

## Overview

Лёгкая и быстрая система обмена сообщениями (pub/sub) для .NET с поддержкой:
- типизированных событий без ключа и с ключом (keyed);
- синхронных и асинхронных отправителей/получателей;
- ленивого создания брокеров на каждый тип события;
- интеграции с DI (Autofac), единая точка — `Exchange`.

Цель — простой, прозрачный и безопасный по потокам обмен событиями между сервисами/модулями без лишней связности.

## Features

Интерфейсы отправителей/получателей:
- `ISender<TEvent>`: синхронная отправка события типа `TEvent`.
- `IReceiver<TEvent>`: подписка на события типа `TEvent`.
- `ISender<TKey, TEvent>`: синхронная отправка события типа `TEvent` по ключу `TKey`.
- `IReceiver<TKey, TEvent>`: подписка на события `TEvent`, разделённые по ключу `TKey`.
- `IAsyncSender<TEvent>`: асинхронная отправка события `TEvent`.
- `IAsyncReceiver<TEvent>`: асинхронная подписка на `TEvent`.
- `IAsyncSender<TKey, TEvent>` / `IAsyncReceiver<TKey, TEvent>`: асинхронные keyed-аналоги.

Фабрики/инфраструктура:
- `ISimpleBrokerFactory`, `IKeyedMessageBrokerFactory`: фабрики отправителей/получателей.
- Реестр(ы) брокеров создают по одному брокеру на каждый `TEvent` (и/или `TKey`), переиспользуют существующие.
- `SimpleBroker<TEvent>`, `KeyedBroker<TKey, TEvent>` и их async-версии.
- Совместимость с `ILogger` (детальные события логирования).

DI и модуль:
- `MessagerModule` (Autofac): регистрирует фабрики и адаптеры `Sender<>`/`Receiver<>` и их keyed/async варианты.
- `ContainerBuilderExtensions.AddEventSystem(...)`: быстрая инициализация.

Потокобезопасность:
- Брокеры синхронизируют доступ к подпискам и доставке событий.

Примечания:
- Возвращаемые `IDisposable`/`IAsyncDisposable` необходимо удерживать (или освобождать) в жизненном цикле вашего сервиса.
- Брокеры создаются лениво и переиспользуются: для каждого `TEvent` (и `TKey`) — один экземпляр.
